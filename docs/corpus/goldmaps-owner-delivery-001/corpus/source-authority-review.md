# Native execution and final product source authority

**Review role:** Specialist A, corpus and source custody. This is an independent
scope review of the proposed additive session lifecycle repair. It does not
certify an unbuilt final archive or replace the assurance lane's byte comparison.

Native map evidence may remain valid when a later additive browser/session repair
leaves the qualified native runtime, ordinary Workbench and map inputs unchanged.
The final package must preserve the source at which that evidence actually ran
and separately qualify the repaired product. A later packaging or UI commit is
not a new execution of the old native campaign.

## Four authorities must remain distinct

| Authority | Meaning and required evidence |
| --- | --- |
| Frozen scientific engine and corpus | Engine `662df51cd8409a52332fa7ef15d06d8ab8945aed`, scientific evidence `40f196f792e4d9e19bbd57fdafd6a90420fadf32`, archival closure `b9535405853a5cd16e4bba968ec7167222861c42`. New product work does not rewrite these results. |
| Contemporary native runtime | Accepted CyberSand `00cdb02f103265b6dc5224c68283e9a0c8cb449f`, exact Godot/native/Rapier binaries and the source-matched ordinary Workbench. This authority differs from the delivery repository's source commit. |
| Executed native qualification source | The exact delivery checkout, runner/probe hashes, GitHub run and package manifest at which each real map load/actor/tick/readback/save/reopen case ran. Preserve these fields and raw receipts unchanged. |
| Final product and archive source | The exact additive browser/session source, fresh product/lifecycle/launcher/graphical executions and final archive manifest. This may be later than the retained native qualification source. |

At the reviewed delivery source
`b4ed0fc462a5e10f3d502b4b5593ef9b4ce70041`, the raw native summary already records
`executed_source`, exact code hashes, `github_sha`, `github_run_id`,
`package_before`, `package_after`, `inputs_sha256`, Godot and probe hashes.
The native execution identity can therefore be preserved without modifying
historical raw evidence.

## Requirements for an explicit reuse decision

The independent final auditor should compare the actual earlier downloaded ZIP
with the later final ZIP. A source-tree statement alone does not prove which
files shipped. Preserve both manifest identities and every retained native
summary/receipt/log digest.

The comparison must establish exact agreement for the pinned engine identity,
ordinary Workbench source, source-bound native/Rapier dependencies, Godot binary,
all Setup payloads and native input records, and the qualification runner/probe
files on which the retained result depends. An explicit allowlist explains later
additive product/test/documentation changes; unexpected changes must refuse the
reuse decision. The #183 generator's tracked source hash must remain independently
verified even if its metadata names the later published generator commit.

Fresh product qualification must exercise the repaired New/Load lifecycle,
unchanged initial map admission, editing, named save, cancellation, return to
browser, owner-record preservation and fresh-process reopening in the actual final
package. Actual final launcher and extracted-package checks must use that final
source. Any rendered captures retained from an earlier product source must keep
their earlier source, with newly affected visible behavior checked separately.

No old native record should acquire the final GitHub source/run values. Label the
result as retained native execution with verified unchanged dependencies, then
identify the new product execution separately. If the native campaign is actually
rerun at the final source, its new raw receipts supply that claim directly.

## Fields needed by the owner and downstream consumer

The final per-variant matrix should make these identities independently readable:

- Final `delivery_source_head`, final package manifest identity and final archive.
- Each native campaign's executed source, run, summary/receipt hashes, input
  manifest and runtime identities, with an explicit reuse status when applicable.
- The proof record connecting retained native evidence to the final unchanged
  engine, Workbench and Setup payloads.
- Fresh product/lifecycle and graphical source/run identities, their exact tested
  package manifests and actual executed scope.
- Original map source, separate policy-descendant generator/custody identity,
  frozen scientific verdict and owner decision, kept as independent fields.

The current product QA summary binds its tested package manifests but should also
record its own executed checkout and runner/probe hashes. This makes a repaired
product's new evidence self-describing alongside the native campaign evidence.
Owner-local decisions and session/screenshot records can additionally retain the
final delivery source and package manifest, while preserving older local records
with their originally observed identities.

## Corpus-export impact

No frozen scientific value or source Setup needs to change for this lifecycle
repair. The immutable collection and knowledge export already point to
`collection/delivery-qualification.v1.json` by exact engine and Setup digest.
That referenced overlay and its per-campaign raw summaries must expose the actual
execution source and any explicit reuse proof. Assembly scheduling fields are not
fresh qualification results.

The expanded knowledge export must not interpret a later product source as a new
native, graphical, artistic or owner result. The original refused #155/#183
identities remain refused; their separate descendants retain their own evidence.
The 81 logical identities and 72 unique Setup bytes remain counts, regardless of
which campaign establishes their runtime status.

## Review disposition

The source separation is sound **conditional on the actual old/new archive byte
comparison and fresh repaired-product evidence**. The assurance lane owns those
executions and independent verification. At review time the final artifact auditor
assumed that every native source/run equalled the final delivery source/run; that
assumption must be replaced by explicit separately verified authorities if reuse
is chosen. Removing the equality check without the replacement proof would not
close the issue.

## Source-only continuation verification

The follow-up review of integration source
`ac3628bf688bf655e438074cbdefe6ba0c5a2d2e` passed the bounded corpus boundary
checks in [reuse-roster-source-review.v1.json](reuse-roster-source-review.v1.json).
The corpus builder was actually executed at both
`b4ed0fc462a5e10f3d502b4b5593ef9b4ce70041` and the reviewed continuation head,
using the same committed generator bytes and immutable source cache. All 72 Setup
payloads and both native-input JSON files were byte-identical. Complete rosters
differed only in the five explicitly allowed generator commit/URL fields; their
remaining source, actor, geometry, scientific, scheduling and owner fields matched.

The first normalizer erased those five fields without proving their replacement
values named the actual authority. This review identified that gap. The revised
code validates the canonical repository/path/URL, actual authority commit,
`commit_bytes_verified` and committed generator hash for both sources, and requires
#183's full nested generator record to equal its collection authority before
normalization.

Eleven hostile metadata fixtures passed: six invalid generator authority changes
were refused, and five non-exception changes to Setup digest, source commit,
native status, variant role and owner acceptance were rejected by full-roster
comparison. No native World ran in this verification. The actual predecessor/final
ZIP comparison and fresh repaired-product execution remain separate gates.
